# Архитектурные решения (ADR)

Общий журнал для `edukit-backend` и `edukit-frontend` (копия в обоих репозиториях). Статусы как в ТЗ: **У** — утверждено владельцем, **Р** — рекомендация, подлежит проверке, **О** — открыто.

| ID | Решение | Статус | Причина / последствия |
|---|---|---|---|
| ADR-0001 | Два репозитория (`edukit-backend`, `edukit-frontend`), модульный монолит | У (ТЗ §6) | Модули добавляются по этапам как папки/проекты; пустые проекты «на будущее» не создаются |
| ADR-0002 | .NET SDK 10.0.401 (LTS), ASP.NET Core / EF Core 10, Npgsql 10.0.4, PostgreSQL 17 + pgvector | Р | Поддерживаемая LTS-ветка. EF Core/Npgsql 11 требуют .NET 11 (STS) — не берём. Версии централизованы в `Directory.Packages.props`, зафиксированы `packages.lock.json`, restore в CI с `--locked-mode` |
| ADR-0003 | Next.js 16.4.6, React 19.3, Tailwind CSS 4.3, shadcn/ui 4.23 (база Radix), Node.js 24 | Р | Актуальные стабильные версии на 25.11.2026; точные версии в `package.json` + `package-lock.json` |
| ADR-0004 | Мультиязычность во frontend встроенными средствами Next.js (сегмент `[locale]`, `next/root-params`, JSON-словари), без next-intl | Р | Совместимо с включённым `cacheComponents` по документации Next 16; меньше зависимостей. Форматирование — `Intl` (KZT, даты) |
| ADR-0005 | Язык по умолчанию при отсутствии подходящего `Accept-Language` — `ru` | У (25.11.2026) | Решение владельца. Посетитель всегда может переключить язык |
| ADR-0006 | OpenAPI генерируется при сборке backend в `docs/openapi/EduKit.Api.json`; frontend хранит копию в `contracts/openapi.json` и генерирует типы (`openapi-typescript`) | Р (ТЗ §6) | CI backend падает, если документ устарел. Порядок выпуска: backend PR → frontend PR |
| ADR-0007 | Серверные флаги модулей в таблице `feature_flags`; неизвестный/отсутствующий флаг = выключен; все модули выключены | У/Р (ТЗ §11, AC-29) | UI скрывает выключенное по `/api/v1/system/info`, но проверку выполняет сервер. Отдельный флаг `billing.real-payments` |
| ADR-0008 | На этапе 0 зарегистрирован только `MockAiProvider`; ключи реальных AI не нужны и не хранятся | У (ТЗ §9, бюджет) | Реальные адаптеры — этапы 2–3 после разрешения владельца. Ответ mock помечен `"mock": true` |
| ADR-0009 | Frontend обращается к API с сервера Next.js (`EDUKIT_API_URL`); схема для браузера (same-origin прокси, cookies, CSRF) выбирается на этапе 1 | Р (ТЗ §8) | Не открываем CORS до выбора auth-схемы |
| ADR-0010 | Ошибки — ProblemDetails с `correlationId`; заголовок `X-Correlation-Id` принимается только безопасного формата | Р (ТЗ §8) | Защита от внедрения в логи и заголовки |
| ADR-0011 | Дизайн-токены Ocean Blue в hex, радиусы ≤ 4 px; в тёмной теме primary = #60A5FA | Р (ТЗ §5) | #2563EB на тёмном фоне даёт контраст < 4.5:1. Контраст проверяется тестом |
| ADR-0012 | Шрифт Noto Sans через `next/font` с наборами `latin`, `cyrillic`, `cyrillic-ext` | Р → проверить UX | Казахские Ә Ғ Қ Ң Ө Ұ Ү Һ І отображаются (проверено снимками и E2E); окончательно — UX-проверка с преподавателями (ТЗ §14 P1) |
| ADR-0014 | Content-Security-Policy для frontend (nonce, совместимо с Cache Components) и HSTS вводятся на этапе 1 вместе с формами входа | **О** → этап 1 | Сейчас на сайте нет форм и пользовательских данных; заголовки nosniff, X-Frame-Options, Referrer-Policy, Permissions-Policy уже включены. HSTS — на уровне TLS-терминации в staging/production |
| ADR-0013 | Интеграционные тесты — настоящий PostgreSQL (`pgvector/pgvector:pg17`) через Testcontainers | Р (ТЗ §12) | Требуется Docker локально и в CI |
| ADR-0015 | Аутентификация: ASP.NET Core Identity (хеш пароля, блокировка, одноразовые токены) + собственные серверные сессии: случайный токен в HttpOnly cookie `edukit_session`, в БД только SHA-256 | Р | Нужен список входов и завершение любого из них (ТЗ FR-01, AC-02); cookie-аутентификация Identity этого не даёт |
| ADR-0016 | CSRF: изменяющие запросы к `/api` обязаны нести `X-EduKit-Csrf: 1`; cookie SameSite=Lax; CORS не открывается. Браузер обращается к API через same-origin прокси Next.js | Р (ТЗ §8) | Паттерн OWASP «custom request headers». Закрывает ADR-0009 |
| ADR-0017 | Сессии: учитель и ученик — 14 дней без активности (предел 90 дней), привилегированные роли — 12 часов; без «Запомнить меня» cookie живёт до закрытия браузера | У (25.11.2026) | Решение владельца; значения в `SessionPolicy` |
| ADR-0018 | Ученик без email: регистрация по приглашению класса, сам задаёт логин и пароль; пароль сбрасывает классный руководитель | У (25.11.2026) | Часть 1.2. Приглашения классов полностью — этап 7 |
| ADR-0019 | Вход по телефону/SMS — не на этапе 1 | У (25.11.2026) | Без затрат на SMS; адаптер позже |
| ADR-0020 | Вход через Google — на этапе 1 (часть 1.3); ключ OAuth создаёт владелец | У (25.11.2026) | Аккаунты не связываются без доказательства владения email (ТЗ FR-01) |
| ADR-0021 | Совмещение должностей разрешено: один аккаунт, несколько назначений в учреждении, переключение кабинетов | У (25.11.2026) | Назначения — этап 7; базовые роли аккаунта: Staff, Student, PlatformAdmin |
| ADR-0022 | Ответы регистрации и восстановления не раскрывают существование email; повторная регистрация шлёт владельцу письмо «почта уже зарегистрирована»; неверный пароль, неизвестный логин и блокировка дают одинаковый ответ | Р (ТЗ §10) | Причина «почта не подтверждена» сообщается только при верном пароле |
| ADR-0023 | Письма через SMTP; в разработке — Mailpit (письма не уходят наружу). Провайдер для staging/production — **О** (регион хранения, ТЗ §10) | Р | |
| ADR-0024 | Пароль: от 10 до 128 символов, без обязательных спецсимволов (NIST SP 800-63B); 5 неудачных попыток — блокировка на 15 минут; лимит частоты для /auth — 10 запросов в минуту с IP | Р | |
| ADR-0025 | Адрес клиента за прокси: `X-Forwarded-For` принимается только от доверенных адресов (`Network:TrustedProxies`, по умолчанию loopback), `ForwardLimit=1`. Прокси Next.js передаёт адрес клиента только при `EDUKIT_TRUST_UPSTREAM_PROXY=true` (за своим балансировщиком) | Р | Иначе лимит частоты считался бы общим на всех пользователей (ревью 1.1, M3). Топология staging/production — этап 10 |
| ADR-0026 | Письма ставятся в очередь в памяти и отправляются фоновой службой; не больше 5 писем одного вида на адрес в час | Р | Время ответа и сбои SMTP не раскрывают существование аккаунта; защита чужого ящика (ревью 1.1, M1/M2). При перезапуске неотправленные письма теряются — пользователь запросит повторно; надёжная очередь позже |
| ADR-0027 | Ключи Data Protection (подписи ссылок из писем) хранятся в таблице `data_protection_keys` | Р | Ссылки переживают перезапуск и работают на нескольких экземплярах (ревью 1.1, L4). **Открыто для production:** шифрование ключей в хранилище (секрет-менеджер/сертификат) |
| ADR-0028 | Блокировка после 5 неверных паролей на 15 минут сохраняется, несмотря на риск, что злоумышленник специально заблокирует чужой аккаунт | Р, принятый риск | Защита от подбора важнее; смягчение — лимит частоты по IP. Пересмотреть после пилота (CAPTCHA или задержки вместо блокировки) |

## Открытые вопросы, влияющие на ближайшие этапы

Полный список — ТЗ §14. Для этапа 1 критичны:

- Решены владельцем 25.11.2026: язык по умолчанию, вход ученика, телефон, совмещение должностей, Google, сроки сессий (ADR-0005, 0017–0021).
- P0 (остаётся): полная матрица полномочий замдиректора и делегирования (ТЗ §3) — к этапу 7.
- О: почтовый провайдер для staging/production (ADR-0023).
