## Этап 02 — AI vertical slice (КСП)

### Часть 2.6 — личная библиотека (frontend)

**Статус:** готово; ждёт CI. «Мои документы» — библиотека: поиск по названию и фильтр по виду (обычная форма GET, условия в адресе), «Найдено: N», страницы по 20, у каждого документа — копия, «Word», «PDF», удаление с подтверждением; пустой результат поиска — своё состояние с «Сбросить». В кабинете учителя — три последних документа и ссылка «Все документы». Название копии — на языке интерфейса («(копия)», «(көшірме)», «(copy)»), укорачивается до 200 символов. Проверено на 1440 и 360 px (снимки экрана). Проверки: lint, typecheck, Vitest 104/104, build — ✅; Playwright с backend — 56 пройдено, 22 пропущено.

«Сбросить» — обычная ссылка с полной загрузкой страницы (как у формы), чтобы поля поиска гарантированно очищались; это проверяет E2E.

## Этап 01 — учётные записи

### Часть 1.3 — вход через Google (frontend)

**Статус:** реализовано и проверено локально с backend (тестовый, не настоящий ключ Google); ждёт CI. Сливать после backend PR этой части и после frontend PR части 1.2 (ветка основана на ней).

- Кнопки «Войти через Google» и «Зарегистрироваться через Google» — только если сервер сообщает, что ключ настроен (`/auth/providers`). Кнопка — обычная ссылка на сервер; «Запомнить меня» и адрес возврата передаются.
- Возврат с Google: сообщения об ошибках по коду в адресе (`?error=google_…`, неизвестные значения игнорируются), шаг ввода кода при `?step=mfa`.
- «Безопасность»: блок «Вход через Google» — статус, «Подключить Google», «Отключить Google» (нельзя без пароля — подсказка), сообщения о результате подключения.
- Прокси `/api/v1/*` передаёт заголовок `location` (перенаправления входа).
- Тесты: lint, typecheck — без замечаний; Vitest 84/84; build — успешно; Playwright без API — 50 пройдено, 20 пропущено; с API без ключа Google — кнопки нет; с API, тестовым ключом Google и Mailpit — 58 пройдено, 12 пропущено (на 1440 и 360 px): параметры перехода на Google (PKCE S256, state, nonce, адрес возврата, без секрета), отмена на Google, подмена state, подключение из «Безопасности».
- Найдено и исправлено: проверка «включён ли Google» попадала под лимит частоты входа на сервере — после нескольких открытий страницы входа кнопка пропадала. Перенаправление на Google браузер выполняет сам, поэтому тесты не переходят на настоящий Google, а проверяют адрес перехода.

### Часть 1.2 — двухэтапный вход и администрирование (frontend)

**Статус:** реализовано и проверено локально вместе с backend; ждёт CI. Сливать после backend PR этой части.

- Вход в два шага: после пароля — код из приложения-аутентификатора или резервный код; ошибки кода переводятся по машинным кодам сервера.
- Страница «Безопасность» (`/settings/security`): QR-код (библиотека `uqr`, рисуется как SVG без вставки HTML) и ключ для ручного ввода → подтверждение кодом → 10 резервных кодов (скачать, скопировать). Для включённого входа — новые резервные коды и отключение (учителю; администратору отключать нельзя).
- Администратор без настроенного второго фактора после пароля попадает на настройку; при попытке открыть `/admin` сервер отвечает 403, страница ведёт к настройке. Учитель в `/admin` видит «Нет доступа».
- Админ-раздел (`/admin`): сводка (пользователи, сотрудники, администраторы, с двухэтапным входом), включение/выключение модулей (защищённые флаги — «Только на сервере»), журнал аудита. Права проверяет сервер.
- Кабинет учителя: ссылки «Безопасность» и (для администратора) «Администрирование».
- Тесты: lint, typecheck — без замечаний; Vitest 75/75; build — успешно; Playwright без API — 40 пройдено, 12 пропущено (живые сценарии); Playwright с API, Mailpit и `E2E_BACKEND_DIR` — 42 пройдено, 10 пропущено (сценарии «API выключен»), на 1440 и 360 px: учитель включает двухэтапный вход, входит по коду и по резервному коду, неверный код; администратор обязан настроить вход, затем включает/выключает модуль и видит запись в журнале. `npm audit --omit=dev` — 0 уязвимостей.
- Найдено и исправлено: администратор без второго фактора на `/admin` видел «Нет доступа» вместо перехода к настройке. `package-lock.json` после установки `uqr` на Windows терял Linux-зависимости — пересоздан в контейнере `node:24.22.3`.

### Часть 1.1 — учитель: формы входа и регистрации (frontend)

**Статус:** реализовано и проверено локально вместе с backend; ждёт CI. Сливать после backend PR этой части.

- Same-origin прокси `/api/v1/*` → EduKit API: cookie сессии остаётся HttpOnly и first-party, CSRF-заголовок, ограничение размера тела, без доверия к X-Forwarded-For от клиента (ADR-0016, ADR-0025).
- Страницы kk/ru/en: регистрация учителя, подтверждение почты (с повторной отправкой), вход с «Запомнить меня», восстановление и смена пароля, кабинет учителя (заготовка), «Мои входы» с завершением сессий, выход. Кнопка «Войти» в шапке.
- Ошибки сервера переводятся по машинным кодам; ошибки полей связаны с полями (`aria-invalid`, `aria-describedby`); показ/скрытие пароля; безопасный `?next=` (только внутренние пути).
- Тесты: Vitest 74/74; Playwright без API 40 пройдено; Playwright с работающим API и Mailpit 38 пройдено (полный сценарий на 1440 и 360 px: регистрация → письмо → подтверждение → вход → мои входы → выход; неверный пароль; восстановление пароля; попытка открытого перенаправления).
