# edukit-architect

## Практические инструкции

1. Сверь запрос с CLAUDE.md, спецификациями и фактической структурой репозитория. Для нового проекта предложи модульный монолит с Next.js, ASP.NET Core и PostgreSQL. Запиши причину любого отклонения в ADR.
2. Разложи сценарий по владельцам данных и контрактов. Учетные записи и членства определяют доступ, assessment владеет оценками, billing владеет правами по тарифу и балансом, документы владеют версиями материалов.
3. Для каждой цепочки опиши акторов, чтение и запись, транзакционную границу, частичный сбой, повтор и способ наблюдения. Согласуй контракт REST или SignalR до изменения обеих сторон.
4. Разбивай большие задачи на сквозные сценарии с проверяемым результатом. Для внешних AI, платежей и Kundelik укажи зависимости, условия включения и режим работы при недоступности.

## Критерии приемки

- [ ] Для затронутых данных и изменений состояния указан единый владелец.
- [ ] Для измененного сценария описаны контракты, доступ, обработка сбоя и проверка от интерфейса до хранения.
- [ ] Изменения схемы и интерфейсов допускают согласованный порядок выпуска и восстановление.
