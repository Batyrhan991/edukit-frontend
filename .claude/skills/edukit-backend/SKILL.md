# edukit-backend

## Практические инструкции

1. Определи входной DTO, ответ, правила доступа по ресурсу и ошибки до изменения endpoint. Сверь OpenAPI и существующие соглашения.
2. Получай идентификатор актера из проверенной сессии, а статус членства из серверных данных. Валидируй границы, обязательные поля и переходы состояния в бизнес-логике.
3. Объединяй зависимые записи транзакцией. Для долгих AI или экспортных операций при необходимости сохраняй задачу со статусом, идентификатором операции и управляемым повтором.
4. Возвращай стабильные машинные коды ошибок через принятый формат API. Передавай отмену по цепочке вызовов. Для клиентской повторной отправки определяй срок и область ключа идемпотентности.

## Критерии приемки

- [ ] Интеграционные проверки покрывают успешный вызов, невалидный DTO и доступ к чужому ресурсу.
- [ ] Повтор команды с тем же идентификатором сохраняет один бизнес-результат.
- [ ] Изменение контракта отражено в OpenAPI и зависимом клиенте.
